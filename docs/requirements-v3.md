# 📋 Функциональные требования AI Review Analyzer

## 1. Функциональные требования

### UC1 — Регистрация и вход
- ✅ **FR‑1.** Система должна предоставлять пользователю возможность создать учётную запись.  
- ✅ **FR‑2.** Система должна проверять корректность введённых регистрационных данных.  
- ✅ **FR‑3.** Система должна сохранять новый аккаунт в базе данных.  
- ✅ **FR‑4.** Система должна авторизовать пользователя после успешной регистрации.  
- ✅ **FR‑5.** Система должна информировать пользователя об ошибках при некорректных данных.  

---

### UC2 — Выход из аккаунта
- ✅ **FR‑6.** Система должна предоставлять кнопку/ссылку для выхода из системы.  
- ✅ **FR‑7.** Система должна завершать сессию пользователя при выходе.  
- ✅ **FR‑8.** Система должна перенаправлять пользователя на страницу входа после выхода.  
- ✅ **FR‑9.** Система должна очищать сессионные данные и токены доступа.  

---

### UC3 — Добавление нового проекта (запуск анализа)
- ✅ **FR‑10.** Система должна предоставлять форму для добавления нового проекта (URL товара).  
- ✅ **FR‑11.** Система должна валидировать URL маркетплейсов (Wildberries, Ozon).  
- ✅ **FR‑12.** Система должна запускать процесс сбора отзывов с указанного URL.  
- ✅ **FR‑13.** Система должна обрабатывать отзывы через LLM для анализа тональности.  
- ✅ **FR‑14.** Система должна сохранять результаты анализа в базе данных.  

---

### UC4 — Запуск повторного анализа
- ✅ **FR‑15.** Система должна предоставлять возможность повторного анализа существующего проекта.  
- ✅ **FR‑16.** Система должна обновлять данные отзывов при повторном анализе.  
- ✅ **FR‑17.** Система должна пересчитывать аналитику с учётом новых данных.  
- ✅ **FR‑18.** Система должна сохранять историю изменений аналитики.  

---

### UC5 — Просмотр ранее проанализированных проектов
- ✅ **FR‑19.** Система должна отображать список всех проанализированных проектов.  
- ✅ **FR‑20.** Система должна предоставлять фильтрацию проектов по статусу и дате.  
- ✅ **FR‑21.** Система должна отображать основные метрики каждого проекта (рейтинг, кол-во отзывов).  
- ✅ **FR‑22.** Система должна предоставлять возможность быстрого доступа к деталям проекта.  

---

### UC6 — Просмотр конкретного проекта
- ✅ **FR‑23.** Система должна отображать детальную аналитику выбранного проекта.  
- ✅ **FR‑24.** Система должна визуализировать распределение тональности отзывов (графики).  
- ✅ **FR‑25.** Система должна отображать список выявленных проблем и их частоту.  
- ✅ **FR‑26.** Система должна предоставлять сгенерированные рекомендации по улучшению.  
- ✅ **FR‑27.** Система должна показывать историю изменений метрик проекта.  

---

## 2. Definition of Done (DoD) для функций

Функция считается завершённой, если:

- **Реализована в коде и доступна через UI (HTML/CSS) или API (FastAPI).**  
  - UC1–UC2: регистрация, вход и выход выполняются через форму на сайте.  
  - UC3: добавление проекта через URL, валидация и запуск анализа доступны.  
  - UC4: повторный анализ работает для существующих проектов.  
  - UC5: список проектов с фильтрацией отображается в личном кабинете.  
  - UC6: детальная аналитика проекта с графиками доступна.  

- **Протестирована по критериям приёмки.**  
  Для каждого UC проверяется:  
  - корректные данные → успешный сценарий,  
  - некорректные данные → сообщение об ошибке.  
  Все реализованные UC прошли тестирование и работают end‑to‑end.

- **Данные сохраняются в базе данных и доступны через API/UI.**  
  - UC1–UC2: аккаунты пользователей и сессии.  
  - UC3–UC4: проекты, отзывы, результаты анализа.  
  - UC5–UC6: метрики проектов, аналитика, рекомендации.  

- **Документация обновлена.**  
  - API описан в OpenAPI/Swagger.  
  - README содержит инструкции по запуску и проверке функций.  
  - Руководство пользователя доступно в разделе Help.

- **Нет критических багов, функция проходит интеграционный тест.**  
  Интеграционный тест — сквозной сценарий:  
  1. Пользователь регистрируется.  
  2. Входит в систему.  
  3. Добавляет новый проект (URL товара).  
  4. Запускает анализ отзывов.  
  5. Просматривает список своих проектов.  
  6. Открывает детальную аналитику проекта.  
  7. Запускает повторный анализ.  
  Если весь путь работает без ошибок и бизнес‑метрики достигнуты (точность ≥ 85%, время ответа ≤ 500 мс, удовлетворённость ≥ 80%), функция считается завершённой.

## 3. North Star Metric

**Снижение доли негативных отзывов у пользователей относительно исходного уровня.**

### Целевые значения:
**Минимальная цель:** снижение на 15% за 3 месяца
**Целевое значение:** снижение на 25% за 6 месяцев
**Отличный результат:** снижение на 40% за 12 месяцев

### Вспомогательные метрики:
- **Конверсия добавления проекта:** 78%  
- **Среднее время анализа:** 2.8 минуты  
- **Точность анализа тональности:** 88%  
- **Удовлетворённость пользователей:** 86%
