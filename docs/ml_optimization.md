
## 🧱 Baseline

**`SentimentAnalyzer`**  
Использует `SENTIMENT_PROMPT` и модель `mistral-small` через Mistral API.  
Задача: анализ тональности отзывов (позитивный/негативный/нейтральный).

**`ProblemDetector`**  
Использует `PROBLEM_PROMPT` и модель `mistral-small` через Mistral API.  
Задача: выявление типичных проблем в отзывах ("доставка", "качество", "описание", "сервис").

## ❌ Типовые ошибки и причины

- **Ложноположительные негативы:** сарказм или конструктивная критика. → Добавлена категория "нейтральный с критикой".  
- **Слишком общие категории проблем:** "качество" вместо "некачественный материал". → Введена двухуровневая классификация.  
- **Общие рекомендации:** "улучшить качество" вместо конкретных действий. → Введен шаблон "Проблема → Действие → Результат".

## 📋 Чеклист промпта

### Обязательные поля для анализа тональности
- `sentiment` (позитивный/нейтральный/негативный/нейтральный с критикой)  
- `confidence` (число 0-1)  
- `key_phrases` (фразы, повлиявшие на оценку)

### Обязательные поля для выявления проблем
- `category` (доставка/качество/описание/сервис/упаковка)  
- `specific_problem` (конкретная формулировка)  
- `severity` (minor/major/critical)

### Правила классификации

**`severity`**:  
  - minor = единичное упоминание, не влияет на рейтинг  
  - major = повторяющаяся проблема, влияет на лояльность  
  - critical = массовые жалобы, угроза рейтингу

### Запреты
- ❌ Субъективные оценки без обоснования  
- ❌ Повторение текста отзыва без анализа  
- ❌ Нарушение формата JSON ответа

## 🧪 Процедура A/B тестирования

1. **Выбор вариантов:** сформировать пары промптов (sentiment_a vs sentiment_b, problem_a vs problem_b).  
2. **Запуск:** прогнать на одинаковом наборе отзывов (1000+ записей).  
3. **Сбор метрик:**  
   - Accuracy, Precision, Recall, F1-Score  
   - Processing time  
   - User satisfaction score  
4. **Анализ:** сравнить средние значения, выбрать победителя по совокупности метрик.  
5. **Фиксация:** задокументировать baseline и причины выбора.
