# Roadmap проекта — AI Review Analyzer

## 1. Введение
Цель roadmap — определить этапы разработки, приоритеты и риски проекта AI Review Analyzer, чтобы обеспечить последовательное достижение MVP и дальнейшее развитие системы анализа отзывов.

## 2. Эпики и спринты
### Спринт 1 (Базовый функционал, 2 недели)
- **Эпик: Аутентификация**
  - Backend API для обработки данных аутентификации
  - Создание и управление пользователями в бд

- **Эпик: Базовая архитектура бекенда**
  - Настройка двух сервисов: Core Service и Consumer Service
  - Конфигурация бд для хранения пользователей
  - Настройка Message Queue для межсервисного взаимодействия
  - Базовые API эндпоинты для аутентификации в Core Service
  - Настройка health-check эндпоинтов

### Спринт 2 (Базовый функционал, 2 недели)
- **Эпик: Парсинг Wildberries в Consumer Service**
  - Разработка парсера для сбора отзывов с Wildberries
  - Извлечение мета-информации о товарах (название, изображение, рейтинг, дата)
  - Валидация URL и обработка ошибок парсинга

- **Эпик: Интеграция с LLM API**
  - Настройка Consumer Service для работы с LLM API
  - Разработка модуля анализа тональности и категоризации аспектов
  - Агрегация статистики и подсчет общего рейтинга
  - Настройка взаимодействия между Core Service и Consumer Service

### Спринт 3 (MVP, 2 недели)
- **Эпик: Генерация рекомендаций через LLM API**
  - Интеграция Consumer Service с LLM API для анализа результатов
  - Формирование конкретных рекомендаций по улучшению товара
  - Структурирование выводов по проблемным аспектам

- **Эпик: Базовый интерфейс пользователя и завершение MVP**
  - Интерфейс добавления товара по ссылке
  - Раздел "Мои товары" с иконками и основной информацией
  - Детальная страница товара с рекомендациями и статистикой
  - Интеграция фронтенда с Core Service API
  - Отображение истории анализов
  - Функция выхода из системы

### Спринт 4 (Расширение возможностей, 2 недели)
- **Эпик: Визуализация данных**
  - Базовые графики распределения тональности
  - Визуальное представление рекомендаций LLM
  - Оптимизация взаимодействия между сервисами

- **Эпик: Управление сессиями**
  - Автоматическое продление сессий
  - Мониторинг работы обоих сервисов

## 3. Зависимости задач
- Аутентификация должна быть готова до разработки личного кабинета
- Архитектура двух сервисов должна быть настроена перед разработкой парсера
- Парсер обязателен перед интеграцией LLM анализа
- Анализ и рекомендации LLM должны быть готовы перед реализацией визуализации
- Система пользователей требуется для привязки товаров и истории анализов

## 4. Приоритизация MVP функций

**MVP (Минимальная версия продукта):**
- Регистрация и вход 
- Архитектура двух сервисов (Core Service + Consumer Service)
- Добавление товара по ссылке на Wildberries
- Парсинг отзывов,их анализ и генерация рекомендаций  через LLM API
- Личный кабинет пользователя
- Детальная страница анализа с рекомендациями и статистикой
- Отображение истории анализов
- Выход из системы

**Функции следующей версии:**
- Реализация ассинхронных вызовов
- Повторный анализ по датам
- Расширенная визуализация с графиками и диаграммами
- Поддержка дополнительных маркетплейсов
- Оптимизация производительности двух сервисов

## 5. Риски и митигация

**Риск: Изменение структуры Wildberries**
- Митигация: Регулярное тестирование парсера, быстрое реагирование на изменения

**Риск: Низкая точность анализа русскоязычных отзывов через LLM**
- Митигация: Тестирование разных LLM провайдеров, настройка промптов под специфику маркетплейсов

**Риск: Ограничения частоты запросов к маркетплейсам**
- Митигация: Кэширование данных в Consumer Service, оптимизация парсинга, очередь запросов

**Риск: Сложность интерфейса для новых пользователей**
- Митигация: Упрощенный онбординг, понятные сообщения об ошибках, демо-режим

**Риск: Проблемы взаимодействия между двумя сервисами**
- Митигация: Тщательное тестирование Message Queue, retry-логика, мониторинг коммуникации

**Риск: Высокая стоимость LLM API**
- Митигация: Оптимизация промптов, кэширование результатов, мониторинг использования
