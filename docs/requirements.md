# 1. Введение
AI Review Analyzer — интеллектуальная система для автоматического сбора и анализа отзывов с маркетплейсов. Система парсит отзывы через быструю авторизацию в Telegram, анализирует тональность, выявляет проблемные аспекты товаров и дает рекомендации по улучшению товара.
Цель проекта — помочь бизнесу быстро выявлять проблемы продуктов, улучшать качество и увеличивать продажи за счет анализа обратной связи клиентов.

# 3. Функциональные требования

**Аутентификация и управление пользователями**
- Регистрация и вход через Telegram Widget
- Автоматическое продление сессий

**Управление товарами и анализом**
- Валидация URL товаров Wildberries
- Парсинг отзывов и метаданных товаров с маркетплейсов
- Анализ тональности, категоризация аспектов и генерация рекомендаций по улучшению через LLM API
- Запуск анализа за произвольные периоды времени
- Визуализация аналитики: графики, дашборды, таблицы

**Управление отчетами и историей**
- Создание и сохранение отчетов об анализе
- Просмотр истории анализов с пагинацией
- Детальный просмотр конкретных анализов
- Сравнение нескольких анализов товара

**Хранение данных:**
- Пользователей (Telegram ID, данные профиля)
- мета-данных анализов
- Истории анализов
- Результатов ML-анализа
- Кэшированных отчетов

**Администрирование:**
- Админ-панель для управления пользователями
- Мониторинг работы парсеров и ML-сервисов

**Безопасность и валидация:**
- Валидация входных данных и URL
- Ограничение частоты запросов на анализ

# 4. Нефункциональные требования и метрики производительности

**Производительность:**
- Среднее время ответа Backend API ≤ 2 секунд (без учёта внешних API)
- 95-й перцентиль времени ответа ≤ 3 секунд
- Время загрузки личного кабинета ≤ 2 секунд
- Среднее время анализа товара (парсинг + NLP + LLM) ≤ 60 секунд для 100 отзывов

**Пропускная способность:** поддержка не менее 50 одновременных пользователей, запускающих анализ

**Доступность:** 
- Backend API ≥ 99% в месяц
- Страница аутентификации через Telegram ≥ 99.5%

**Надёжность:** 
- При сбое внешнего сервиса (NLP, LLM) система возвращает сообщение об ошибке ≤ 3 секунд
- Автоматическое восстановление после временной недоступности парсеров

**Использование ресурсов:** 
- Загрузка CPU ≤ 70% при пиковой нагрузке
- Использование памяти ≤ 75% при пиковой нагрузке

**Безопасность:**
- Аутентификация через Telegram OAuth
- Шифрование соединений (HTTPS)
- Валидация данных от Telegram Widget

**Масштабируемость:**
- Возможность горизонтального масштабирования Backend API
- Кеширование отчетов в Redis

# 5. Технологический стек

**Frontend:** React/Node.js

**Backend:** Python/FastAPI + Celery + Redis

**Database:** MySQL + Redis (кеширование)

**Интеграции:**
- Telegram Widget для аутентификации
- LLM API (анализ тональности,классификация аспектов,генерация рекомендаций по улучшению)

# 6. Архитектурные принципы

Используется модель C4 для описания архитектуры:  
- **Context Diagram** — пользователи и внешние системы ( Маркетплейсы,LLM API)  
- **Container Diagram** — веб-приложение, Backend API, база данных, кеш, парсеры  
- **Component Diagram** — внутренняя структура Backend API (аутентификация, парсинг, ML-интеграция, отчеты)

Backend API реализует бизнес-логику и взаимодействует с внешними сервисами

Данные пользователей, товаров и истории анализа хранятся централизованно в MySQL

Принцип Separation of Concerns: разделение аутентификации, парсинга, ML-анализа, бизнес-логики и слоя данных

Принцип Fail-safe defaults: при сбое внешнего сервиса система возвращает понятное сообщение об ошибке

Event-driven архитектура для длительных операций анализа через Celery

# 7. Ограничения и допущения

LLM API предоставляется как внешнйе сервис (не разрабатываются в рамках проекта)

Система ориентирована на работу в облачной инфраструктуре с горизонтальным масштабированием

Поддерживаются только современные браузеры и десктопные устройства

Генерация рекомендаций через LLM API не гарантирует 100% точности

Парсинг данных зависит от стабильности структуры маркетплейсов

Первоначальная версия поддерживает только маркетплейс Wildberries

Система предназначена для анализа существующих отзывов, а не прогнозирования будущих оценок
