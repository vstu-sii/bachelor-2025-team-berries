# Use-case Narrative: Запустить новый анализ 

## 1. Краткое описание
Пользователь запускает новый анализ существующего товара за выбранный временной период. Система парсит только новые отзывы, появившиеся с момента последнего анализа, и обновляет статистику товара.

## 2. Участники (Actors)
- **Пользователь:** Аутентифицированный пользователь, владелец товара
- **Парсер маркетплейса:** Система сбора данных с маркетплейсов
- **ИИ-анализатор:** ML-модель для анализа тональности
- **Система управления данными:** Хранение и обновление истории анализов

## 3. Pre-conditions
- Пользователь аутентифицирован и находится на странице конкретного товара
- Товар имеет как минимум один предыдущий анализ
- Система парсера и ИИ-анализатора доступны

## 4. Post-conditions
- **Успех:** Создан новый анализ за выбранный период, статистика товара обновлена
- **Неудача:** Пользователь получает сообщение об ошибке с объяснением причины

## 5. Детальные сценарии

### 5.1. Happy Path (Основной успешный сценарий)

| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь на странице товара нажимает кнопку "Новый анализ" | Система открывает диалоговое окно выбора периода анализа |
| 2 | Пользователь выбирает период: "За последнюю неделю", "За последний месяц" или указывает даты | ... |
| 3 | Пользователь подтверждает запуск анализа "Запустить" | Система закрывает диалог и показывает индикатор прогресса |
| 5 | ... | Парсер собирает только новые отзывы за выбранный период |
| 6 | ... | ИИ-модель анализирует новые отзывы, определяя тональность и ключевые аспекты |
| 9 | ... | Система обновляет интерфейс, показывая графики и метрики |

**Ценность для пользователя:**
- **Актуальность данных:** Получение самой свежей информации о товаре
- **Эффективность:** Анализ только новых отзывов экономит время и ресурсы


### 5.2. Alternative Flows (Альтернативные сценарии)

#### A.1: Анализ за кастомный период
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь выбирает "Произвольный период" в диалоге анализа | Система показывает календари для выбора начальной и конечной даты |
| 2 | Пользователь выбирает даты начала и окончания периода | Система валидирует период (не более 90 дней, не в будущем) |
| 3 | ... | Если период некорректен, система показывает сообщение с требованиями |
| 4 | Пользователь подтверждает корректный период | Система запускает анализ только за выбранные даты |
| 5 | ... |  Система обновляет интерфейс, показывая графики и метрики  |

**Ценность для пользователя:**
- **Гибкость:** Возможность анализировать конкретные периоды (акции, сезоны, после изменений товара)
- **Точный контроль:** Пользователь сам определяет релевантные временные рамки

#### A.2: Новых отзывов не найдено
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь запускает анализ за период | Парсер не находит новых отзывов за выбранный период |
| 2 | ... | Система анализирует результат парсера (пустой список отзывов) |
| 3 | ... | Система не запускает ИИ-анализ для экономии ресурсов |
| 4 | ... | Система показывает информационное сообщение: "За выбранный период новых отзывов не найдено. Статистика не изменилась." |
| 5 | ... | Создается запись в истории анализов с отметкой "Нет новых данных" |

**Ценность для пользователя:**
- **Прозрачность:** Четкое понимание результатов операции
- **Экономия ресурсов:** Избежание бесполезной обработки данных

### 5.3. Error Handling (Обработка ошибок)

#### E.1: Превышение лимита частоты анализов
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь пытается запустить анализ слишком часто | Система проверяет время последнего анализа этого товара |
| 2 | ... | Обнаружено, что предыдущий анализ был менее 24 часов назад |
| 3 | ... | Система блокирует запуск и показывает сообщение: "Слишком частые анализы. Подождите X минут перед следующим анализом." |

**Ценность для пользователя:**
- **Защита от злоупотреблений:** Предотвращение перегрузки системы
- **Обучение:** Понятное объяснение ограничений системы

#### E.2: Изменение структуры страницы маркетплейса
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь запускает анализ | Парсер возвращает ошибку из-за изменений в структуре страницы |
| 2 | ... | Система определяет, что парсер не может найти элементы на странице |
| 3 | ... | Система показывает сообщение: "Временно не удается получить данные с маркетплейса. Мы уже работаем над решением." |
| 4 | ... | Система предлагает повторить попытку через несколько часов |

**Ценность для пользователя:**
- **Честная коммуникация:** Понятное объяснение технических проблем
- **Минимизация фрустрации:** Пользователь не думает, что проблема на его стороне

    S -->|Показ ошибки| B
    U -->|Показ ошибки| B
