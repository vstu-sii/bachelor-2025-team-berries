# Контроль интеграции Product Reviews Analysis System
## Сценарий проверки (MVP)
1. Аутентификация через Telegram
2. Добавление товара по ссылке Wildberries
3. Парсинг отзывов с маркетплейса
4. Анализ тональности и выявление проблемных аспектов (Backend вызывает ML пайплайн для анализа отзывов)
5. Генерация отчета с рекомендациями (Система передает результаты анализа в LLM для создания сводки)
6. Просмотр аналитики с графиками и диаграммами
7. Сравнение разных периодов анализа

## Фактическое состояние:
1. Аутентификация - не реализована
2. Backend API - базовый каркас реализован (FastAPI)
3. ML пайплайн - preprocessing реализован, интеграция с моделями не готова
4. PostgreSQL - СУБД подключена и работает в Docker
5. Frontend/UI - не реализован
6. Docker инфраструктура - настроена для тестовых данных
7. Мониторинг - Grafana, Prometheus, Loki работают
8. CI/CD - GitHub Actions настроен

## Проверка работы всех компонентов:
**Docker инфраструктура ↔ Все сервисы:** соединение установлено, все контейнеры запускаются.  
**FastAPI ↔ PostgreSQL:** подключено, тестовый эндпоинт `/db-test` работает.  
**Jupyter ↔ PostgreSQL:** база доступна для экспериментов и работы с данными.  
**Grafana ↔ Prometheus/Loki:** источники данных настроены, метрики и логи собираются.  
**GitHub Actions ↔ Docker Hub:** автоматический деплой настроен, CI/CD пайплайн работает.  
**FastAPI ↔ ML пайплайн:** не подключено - существующий Python код не интегрирован с API.  
**LLM сервис ↔ Приложение:** контейнер запущен, но веб-сервис не работает.

## Найденные проблемы
- Нет полноценного end‑to‑end сценария - компоненты работают изолированно.
- ML пайплайн не интегрирован с основной системой - preprocessing код существует отдельно.
- LLM сервис настроен, но не функционален внутри контейнера.
- UI отсутствует, нет способа взаимодействия с системой для пользователя.
- Аутентификация через Telegram не реализована 
- Парсинг Wildberries не интегрирован - нет механизма сбора данных.
