# Контроль интеграции Product Reviews Analysis System
## Сценарий проверки (MVP)
1. Аутентификация через Telegram
2. Добавление товара по ссылке Wildberries
3. Парсинг отзывов с маркетплейса
4. Анализ тональности и выявление проблемных аспектов (Backend вызывает ML пайплайн для анализа отзывов)
5. Генерация отчета с рекомендациями (Система передает результаты анализа в LLM для создания сводки)
6. Просмотр аналитики с графиками и диаграммами
7. Сравнение разных периодов анализа

## Фактическое состояние:
1. **Аутентификация** - Полностью реализована
2. **Backend API** - Работает на Express.js, реализованы CRUD для проектов и продуктов, но нет бизнес-логики анализа
3. **Парсер** - Не реализовано
4. **ML пайплайн** - Preprocessing реализован, интеграция с LLM моделями не готова
5. **База данных** - СУБД подключена и работает в Docker
6. **Frontend/UI** - Реализован интерфейс личного кабинета пользователя,навигация,просмотр карточки конкретного товара. Ключевые функции не активны (анализ, сравнение), так как нет интеграции с LLM
7. **Docker инфраструктура** - Реализована
8. **Мониторинг** - Grafana, Prometheus, Loki, Langfuse работают
9. **CI/CD** - GitHub Actions настроен 
10. **LLM сервис** - Не реализовано
11. **AI промпты** - Шаблоны для анализа отзывов разработаны

## Проверка работы всех компонентов:
- **Docker инфраструктура** ↔ **Все сервисы**: все контейнеры запускаются
- **Express.js** ↔ **MySQL**: подключение работает
- **Jupyter** ↔ **MySQL**: база доступна для экспериментов
- **Grafana** ↔ **Prometheus/Loki/Langfuse**: источники данных настроены
- **GitHub Actions** ↔ **Docker Hub**: автоматический деплой работает
- **Express.js** ↔ **Docker**: бэкенд запускается в контейнере
- **ML preprocessing** ↔ **Данные**: код работает локально, но не в Docker
- **AI промпты** ↔ **LLM**: шаблоны готовы, но нет вызовов моделей
- **Express.js** ↔ **ML пайплайн**: нет эндпоинтов для анализа
- **LLM сервис** ↔ **Приложение**: контейнер запущен, но веб-сервис не отвечает
- **Пользователь** ↔ **Система**: есть пользовательский интерфейс
- **Система** ↔ **Wildberries**: нет парсинга отзывов

## Найденные проблемы
1. **Отсутствует ключевая функциональность** — система не выполняет свою основную задачу: сбор и анализ отзывов.
2. **Нет интеграции компонентов** — бэкенд, ML-пайплайн и LLM работают изолированно.
3. **LLM-сервис не функционирует** — контейнер запущен, но не предоставляет API для анализа.
4. **Отсутствует парсинг данных** — нет механизма получения отзывов с маркетплейсов.
5. **Мониторинг настроен, но не используется** — Langfuse и Prometheus не интегрированы с LLM.
6. **CI/CD без проверки функциональности** — пайплайн собирает контейнеры, но не тестирует интеграции

## Координация исправлений
### Fullstack (Бэкенд + Фронтенд):
1. Реализовать эндпоинты для запуска анализа отзывов.
2. Создать парсер для получения данных с Wildberries.
3. Интегрировать фронтенд с рабочим бэкендом для отображения результатов анализа.

### AI Engineer (ML/LLM):
1. Интегрировать preprocessing-код с LLM (вызовы Mistral/Ollama).
2. Настроить промпты для анализа тональности и генерации рекомендаций.
3. Создать baseline-модель анализа отзывов.

### MLOps (Docker/Infrastructure/CI):
1. Контейнеризировать ML-пайплайн и добавить в docker-compose.
2. Настроить метрики ML-моделей в Prometheus.
3. Добавить интеграционные тесты в CI/CD пайплайн.
   
### SA/PO (Документация/Интеграция):
