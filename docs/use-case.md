# Use-case Narrative: Регистрация через Telegram

## 1. Краткое описание
Новый пользователь регистрируется в системе с помощью Telegram аккаунта через Telegram Widget. После успешной аутентификации создается профиль пользователя и предоставляется доступ к личному кабинету.

## 2. Участники (Actors)
- **Пользователь:** Новый пользователь, имеющий аккаунт в Telegram
- **Telegram Auth System:** Внешняя система аутентификации Telegram
- **Система анализа отзывов:** Наша платформа
- **База данных:** 
    
## 3. Pre-conditions
- Пользователь имеет установленное приложение Telegram на устройстве
- Пользователь имеет активный аккаунт Telegram
- Telegram Widget доступен и функционирует нормально

## 4. Post-conditions
- **Успех:** Создан новый профиль пользователя, пользователь аутентифицирован в системе, открыт личный кабинет
- **Неудача:** Пользователь остается на главной странице без доступа к функциям анализа

## 5. Детальные сценарии

### 5.1. Happy Path (Основной успешный сценарий)

| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь заходит на главную страницу сайта | Система отображает "Регистрация через Telegram" |
| 2 | Пользователь нажимает "Регистрация через Telegram" | Система отображает Telegram Widget для авторизации |
| 3 | Пользователь вводит свои данные Telegram в виджет и подтверждает вход | Система возвращает данные пользователя (id) |
| 4 | ... | Система проверяет существование пользователя с таким Telegram ID в базе данных |
| 5 | ... | Система определяет, что пользователь новый, и создает запись в базе данных |
| 6 | ... | Система сохраняет данные |
| 7 | ... | Система перенаправляет пользователя в личный кабинет с доступом ко всем функциям |

**Ценность для пользователя:**
- **Мгновенная регистрация:** Процесс занимает 1-2 клика без заполнения форм
- **Безопасность:** Использование защищенной аутентификации через Telegram
- **Удобство:** Не требуется запоминать пароли или подтверждать email

### 5.2. Alternative Flows (Альтернативные сценарии)

#### A.1: Пользователь уже существует (повторная регистрация)
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь нажимает "Регистрация через Telegram" | Система отображает Telegram Widget |
| 2 | Пользователь подтверждает авторизацию | Система получает данные Telegram |
| 3 | ... | Система определяет, что пользователь уже существует в базе данных |
| 4 | ... | Система показывает сообщение: "Пользоваель уже существует" и возвращает на главную сраницу |


### 5.3. Error Handling (Обработка ошибок)

#### E.1: Telegram Widget недоступен
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь нажимает регистрацию | Telegram Widget не загружается (таймаут или ошибка сети) |
| 2 | ... | Система обнаруживает ошибку загрузки виджета |
| 3 | ... | Система показывает сообщение: "Telegram временно недоступен. Пожалуйста, попробуйте позже." |
| 4 | ... | Система предлагает повторить попытку через 5 минут |

**Ценность для пользователя:**
- **Понятная обратная связь:** Пользователь понимает причину проблемы
- **Рекомендации:** Предлагаются конкретные действия для решения

#### E.2: Пользователь отменяет авторизацию в Telegram
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь открывает Telegram Widget | Система запрашивает разрешение на авторизацию |
| 2 | Пользователь нажимает "Отмена" | Система возвращает ошибку отмены авторизации |
| 3 | ... | Система обрабатывает ошибку и показывает сообщение: "Регистрация отменена. Для использования системы требуется войти через Telegram." |
| 4 | ... | Система возвращает пользователя на главную страницу |
