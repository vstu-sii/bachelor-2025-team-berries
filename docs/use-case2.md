# Use-case Narrative: Вход через Telegram

## 1. Краткое описание
Существующий пользователь входит в систему с помощью Telegram аккаунта через Telegram Widget. После успешной аутентификации пользователь получает доступ к личному кабинету с историей анализов.

## 2. Участники (Actors)
- **Пользователь:** Зарегистрированный пользователь системы
- **Telegram Auth System:** Внешняя система аутентификации Telegram
- **Система анализа отзывов:** Наша платформа
- **База данных:**
  
## 3. Pre-conditions
- Пользователь уже зарегистрирован в системе
- Пользователь имеет установленное приложение Telegram на устройстве
- Telegram Widget доступен и функционирует нормально

## 4. Post-conditions
- **Успех:** Пользователь аутентифицирован в системе, открыт личный кабинет с доступом к истории анализов
- **Неудача:** Пользователь остается на главной странице без доступа к функциям анализа

## 5. Детальные сценарии

### 5.1. Happy Path (Основной успешный сценарий)

| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь заходит на главную страницу сайта | Система отображает главную страницу с "Войти через Telegram" |
| 2 | Пользователь нажимает "Войти через Telegram" | Система отображает Telegram Widget для авторизации |
| 3 | Пользователь вводит свои данные Telegram | Telegram Widget возвращает данные пользователя (id) |
| 4 | ... | Система проверяет существование пользователя с таким Telegram ID в базе данных |
| 5 | ... | Система определяет, что пользователь существует, и обновляет время последнего входа |
| 6 | ... | Система перенаправляет пользователя в личный кабинет |

**Ценность для пользователя:**
- **Быстрый доступ:** Вход в систему занимает секунды
- **Безопасность:** Не требуется ввод пароля, используется защищенная аутентификация Telegram

### 5.2. Alternative Flows (Альтернативные сценарии)

#### A.1: Автоматический вход при активной сессии
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь заходит на сайт с того же устройства | Система проверяет наличие активной сессии |
| 2 | ... | Если сессия активна и токен валиден, система автоматически перенаправляет в личный кабинет |
| 3 | Пользователь сразу видит личный кабинет | 

**Ценность для пользователя:**
- **Непрерывность работы:** Мгновенный доступ к системе без повторной аутентификации
- **Удобство:** Сохранение рабочего контекста между сессиями

#### A.2: Восстановление после истечения сессии
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь заходит на сайт после длительного перерыва | Система обнаруживает истекшую сессию |
| 2 | ... | Система автоматически перенаправляет на страницу входа |
| 3 | ... | Система показывает сообщение: "Сессия истекла. Пожалуйста, войдите снова." |
| 4 | Пользователь проходит стандартный процесс входа | Система создает новую сессию |

**Ценность для пользователя:**
- **Автоматическое восстановление:** Система сама направляет пользователя на правильный путь
- **Безопасность:** Гарантия, что неактивные сессии не остаются открытыми

### 5.3. Error Handling (Обработка ошибок)

#### E.1: Пользователь не найден в системе
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь пытается войти с Telegram аккаунтом, который не зарегистрирован | Система проверяет базу данных и не находит пользователя |
| 2 | ... | Система показывает сообщение: "Аккаунт не найден. Пожалуйста, зарегистрируйтесь." |
| 3 | Пользователь нажимает кнопку регистрации | Система перенаправляет на процесс регистрации |

**Ценность для пользователя:**
- **Четкое руководство:** Понятное сообщение о необходимом действии
- **Беспрепятственный переход:** Быстрый доступ к регистрации

#### E.2: Проблемы с сетью при входе
| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь подтверждает вход в Telegram Widget | Возникают сетевые проблемы при передаче данных |
| 2 | ... | Система обнаруживает таймаут или сетевую ошибку |
| 3 | ... | Система показывает сообщение: "Не удалось завершить вход. Проверьте подключение к интернету." |
| 4 | ... | Система предлагает кнопку "Повторить попытку" |
| 5 | Пользователь нажимает "Повторить попытку" | Система повторяет процесс аутентификации |

**Ценность для пользователя:**
- **Устойчивость к сбоям:** Система корректно обрабатывает временные сетевые проблемы
- **Простое восстановление:** Легкий способ повторить операцию
