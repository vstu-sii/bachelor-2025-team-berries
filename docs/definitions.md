# DoR/DoD критерии — AI Review Analyzer

## 1. Введение
Цель документа — определить критерии Definition of Ready (DoR) и Definition of Done (DoD) для задач и функций проекта AI Review Analyzer, а также зафиксировать метрики успеха продукта и KPI для каждого спринта.

## 2. Definition of Ready (DoR) для задач
Задача считается готовой к разработке, если:

- Чётко сформулирована и описана в бэклоге
- Имеет понятный бизнес-контекст (зачем нужна)
- Определены входные данные и ожидаемый результат
- Есть критерии приёмки (acceptance criteria)
- Нет блокирующих зависимостей или они явно зафиксированы
- Оценена по трудоёмкости (story points или часы)
- Определен целевой сервис для реализации (Core Service / Consumer Service)

## 3. Definition of Done (DoD) для функций
Функция считается завершённой, если:

- Реализован весь заявленный функционал
- Пройдены unit-тесты и интеграционные тесты
- Код прошёл code review
- Функция задокументирована (README, комментарии, API-спецификация)
- Изменения задеплоены в тестовую среду
- Пользовательский сценарий проверен вручную (acceptance testing)
- Нет критических багов (severity 1–2)
- Настроено межсервисное взаимодействие (для функций, затрагивающих оба сервиса)

## 4. Метрики успеха продукта

**Базовые метрики:**
- Время регистрации через Telegram: ≤ 30 секунд
- Успешный парсинг товаров: ≥ 95% случаев
- Время анализа товара (парсинг + LLM): ≤ 60 секунд для 100 отзывов
- Время отклика UI: ≤ 2 секунд
- Доступность системы: ≥ 99% в рабочее время

**Качество анализа:**
- Точность определения тональности через LLM: ≥ 85%
- Точность категоризации аспектов через LLM: ≥ 80%
- Релевантность рекомендаций LLM: ≥ 75% положительных оценок пользователей

**Пользовательские метрики:**
- Удовлетворённость пользователей (опрос): ≥ 80% положительных оценок
- Количество анализов в месяц: рост на 15% ежеквартально в первые 3 месяца
- Конверсия из посетителя в зарегистрированного пользователя: ≥ 40%

**Технические метрики:**
- Время отклика Core Service API: ≤ 500 мс
- Время обработки задачи Consumer Service: ≤ 45 секунд
- Надёжность Message Queue: ≥ 99.9% доставки сообщений

## 5. KPI для каждого спринта

**Спринт 1: Базовая инфраструктура и аутентификация**
- [ ] Интеграция Telegram Widget для авторизации
- [ ]  Разработка функции выхода из системы
- [ ] Реализация Core Service с API для аутентификации
- [ ] Настройка базы данных для хранения пользователей
- [ ] Базовая архитектура двух сервисов (Core + Consumer)
- [ ] Настройка Message Queue для межсервисной коммуникации

**Спринт 2: Парсинг и интеграция LLM**
- [ ] Разработка парсера в Consumer Service для сбора данных с Wildberries
- [ ] Реализация валидации URL товаров в Core Service
- [ ] Интеграция Consumer Service с LLM API для анализа тональности
- [ ] Настройка категоризации аспектов товаров через LLM
- [ ] Создание системы агрегации статистики отзывов

**Спринт 3: Генерация рекомендаций и интерфейс и завершение MVP**
- [ ] Интеграция Consumer Service с LLM API для генерации рекомендаций
- [ ] Разработка интерфейса добавления товаров (интеграция с Core Service)
- [ ] Создание личного кабинета с разделом "Мои товары"
- [ ] Реализация детальных страниц товаров с анализом
- [ ] Настройка Object Storage для хранения отчетов
- [ ] Создание системы истории анализов в Core Service
- [ ] Health-check эндпоинты для всех компонентов системы

**Спринт 4: Визуализация**
- [ ] Реализация визуализации данных аналитики
- [ ] Нагрузочное тестирование обоих сервисов
- [ ] Мониторинг межсервисного взаимодействия

## 6. Критерии приёмки (Acceptance Criteria)

**Для функций Core Service:**
- [ ] API эндпоинты возвращают корректные HTTP статусы
- [ ] Данные сохраняются в PostgreSQL без потерь
- [ ] Интеграция с Auth Service работает стабильно
- [ ] Message Queue сообщения корректно обрабатываются

**Для функций Consumer Service:**
- [ ] Парсинг данных работает для различных кейсов Wildberries
- [ ] LLM API интеграция обрабатывает ошибки gracefully
- [ ] Данные корректно сохраняются в Object Storage
- [ ] Межсервисная коммуникация с Core Service стабильна

**Для интеграционных функций:**
- [ ] End-to-end сценарии работают от запроса до получения отчета
- [ ] Ошибки в одном сервисе не ломают всю систему
- [ ] Мониторинг показывает корректные метрики по обоим сервисам
