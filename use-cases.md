# Use-case Narrative: Регистрация через Telegram

## 1. Краткое описание
Новый пользователь регистрируется в системе с помощью Telegram аккаунта через Telegram Widget. После успешной аутентификации создается профиль пользователя и предоставляется доступ к личному кабинету.

## 2. Участники (Actors)
- **Пользователь:** Новый пользователь, имеющий аккаунт в Telegram
- **Telegram Auth System:** Внешняя система аутентификации Telegram
- **Система анализа отзывов:** Наша платформа
- **База данных:** 
    
## 3. Pre-conditions
- Пользователь имеет установленное приложение Telegram на устройстве
- Пользователь имеет активный аккаунт Telegram
- Telegram Widget доступен и функционирует нормально

## 4. Post-conditions
- **Успех:** Создан новый профиль пользователя, пользователь аутентифицирован в системе, открыт личный кабинет
- **Неудача:** Пользователь остается на главной странице без доступа к функциям анализа

## 5. Детальные сценарии

### 5.1. Happy Path (Основной успешный сценарий)

| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь заходит на главную страницу сайта | Система отображает "Регистрация через Telegram" |
| 2 | Пользователь нажимает "Регистрация через Telegram" | Система отображает Telegram Widget для авторизации |
| 3 | Пользователь вводит свои данные Telegram в виджет и подтверждает вход | Система возвращает данные пользователя (id) |
| 4 | ... | Система проверяет существование пользователя с таким Telegram ID в базе данных |
| 5 | ... | Система определяет, что пользователь новый, и создает запись в базе данных |
| 6 | ... | Система сохраняет данные |
| 7 | ... | Система перенаправляет пользователя в личный кабинет с доступом ко всем функциям |

**Ценность для пользователя:**
- **Мгновенная регистрация:** Процесс занимает 1-2 клика без заполнения форм
- **Безопасность:** Использование защищенной аутентификации через Telegram
- **Удобство:** Не требуется запоминать пароли или подтверждать email

# Use-case Narrative: Выход из системы

Аутентифицированный пользователь выходит из системы, завершая текущую сессию. После выхода пользователь перенаправляется на главную страницу и теряет доступ к функциям личного кабинета.

## 2. Участники (Actors)
- **Пользователь:** Аутентифицированный пользователь системы
- **Система аутентификации:** Менеджер сессий и JWT токенов

## 3. Pre-conditions
- Пользователь аутентифицирован в системе
- Пользователь находится на главной странице
- Активная сессия пользователя существует

## 4. Post-conditions
- **Успех:** Сессия пользователя завершена, токены удалены, пользователь перенаправлен на главную страницу
- **Неудача:** Сессия остается активной, пользователь остается в личном кабинете

# Use-case Narrative: Запуск анализа

## 1. Краткое описание
Пользователь впервые добавляет товар для анализа путем ввода ссылки на карточку товара с маркетплейса. Система парсит отзывы, анализирует их с помощью ИИ и сохраняет результат в профиле пользователя.

## 2. Участники (Actors)
- **Пользователь:** Аутентифицированный пользователь, добавляющий первый товар
- **Парсер маркетплейса:** Система сбора данных с маркетплейсов
- **ИИ-анализатор:** ML-модель для анализа тональности и аспектов отзывов
- **База данных:** Система хранения результатов анализа

## 3. Pre-conditions
- Пользователь аутентифицирован и находится в личном кабинете
- Пользователь имеет корректную ссылку на товар с поддерживаемого маркетплейса
- Система парсера и ИИ-анализатора доступны и функционируют

## 4. Post-conditions
- **Успех:** Товар добавлен в "Мои товары", проведен анализ, пользователь видит детальный отчет
- **Неудача:** Пользователь получает сообщение об ошибке с объяснением причины

## 5. Детальные сценарии

### 5.1. Happy Path (Основной успешный сценарий)

| Шаг | Действие Пользователя | Ответ Системы |
|-----|----------------------|---------------|
| 1 | Пользователь в личном кабинете видит поле для ввода ссылки и кнопку "Начать анализ" | Система отображает интерфейс добавления первого товара |
| 2 | Пользователь копирует и вставляет ссылку на товар с маркетплейса (Wildberries) | ... |
| 3 | Пользователь нажимает "Начать анализ" | Система показывает индикатор прогресса |
| 4 | ... | Система парсит страницу товара, извлекает все доступные отзывы и метаданные товара |
| 5 | ... | ИИ-модель анализирует отзывы: определяет тональность и ключевые аспекты (качество, доставка, упаковка и т.д.) |
| 6 | ... | Система агрегирует результаты: подсчитывает общую статистику, строит графики распределения |
| 7 | ... | Система сохраняет товар и результаты анализа в базе данных, связывая с пользователем |
| 8 | ... | Система добавляет иконку товара в раздел "Мои товары" с краткой оценкой |
| 9 | ... | Система открывает детальную страницу отчета по проанализированному товару |

**Ценность для пользователя:**
- **Быстрый старт:** Процесс добавления первого товара интуитивно понятен и занимает минимум времени
- **Комплексный анализ:** Получение готовой аналитики без необходимости ручной обработки данных
- **Визуализация результатов:** Наглядное представление данных в виде графиков и диаграмм
